# Codex independent test report

## Summary

Grasp builds and runs, and all 106 automated tests pass. Most of the core workflow also held up under independent command-line testing: incremental diff capture, ordinary mechanical filtering, mock-Claude question generation, cross-project concept memory, positive-cost and question-count caps across a whole session, blank-answer rejection, deliberate skipping, soft and hard gates, repository-specific configuration, errors, timeouts, and slow overlapping generation calls.

This run still found two substantive bugs and two smaller user-facing inconsistencies, so the verdict remains FAIL.

The release-blocking filtering bug from the previous report is only partly fixed. Grasp now catches an existing generated file when its unchanged header is still available on disk, but it does not catch that file when it is deleted. In a clean reproduction, deleting a tracked file headed `// Code generated by a tool. DO NOT EDIT.` passed the filter, invoked Claude, cost $0.006, and created a question about deleting `generated.ts`. Removing obsolete generated outputs is a normal generator operation, so the README's statement that generated files are excluded still does not hold.

The cost parser also accepts a negative `total_cost_usd` as valid. A mock response reporting `-0.5` created a real question and made the stored session total `-0.5`. Because later cap checks compare that total with the configured maximum, malformed negative values can create artificial room under the cap and defeat the safety rail. Valid Claude responses should not report negative cost, but Grasp already promises graceful handling of malformed responses and must reject a non-finite or negative cost rather than treating it as spend.

The smaller issues are an incorrect Escape-key hint in the review UI and missing/inaccurate README requirements: the skip-reason screen says Escape will skip, but a second Escape does nothing; and the README calls Claude authentication the requirement while omitting the package's actual Node 22-or-newer requirement. The README also literally says Grasp performs no file reads beyond the diff, although the generated-file fix now reads up to 4 KB from changed files on disk. That extra header is not sent to Claude, but the wording is no longer accurate.

### Test environment and isolation

- Tested commit `efee2e6` on August 7, 2026, with Node `v26.5.1` and npm `11.17.0`.
- Grasp state, mock logs, counters, and SQLite databases lived under `/private/tmp/grasp-codex-test.QqvE3R`; disposable Git repositories and the custom mock executable lived under the project-local `.codex-test-scratch/` directory.
- The developer's real `~/.grasp/history.db` was neither read nor modified.
- The installed Claude CLI was tested under the disposable home. It accepted Grasp's exact flags but reported `loggedIn: false`, so the repository's established mock-`claude`-on-`PATH` pattern was used for generation tests.
- All disposable state and repositories were removed after testing. Pre-existing untracked files under `loop_logs/` were left untouched.

## 1. Build, automated tests, packaging, and basic CLI — PASS

`npm install` and `npm run build` succeeded. The built CLI printed version `0.1.0`, displayed accurate help for the on-demand `grasp review` design, and created its config and SQLite database only under the disposable home.

`npm test` rebuilt the real CLI first and passed all 106 tests with no failures. The suite covers configuration, filtering, Git parsing, incremental checkpoints, concurrent capture, cap races, store behavior, init output, internal-hook config failures, generated-file regressions, and stale hard gates.

`npm pack --dry-run --json`, run with the disposable npm cache, contained the executable CLI, runtime modules, README, license, and package metadata. The built CLI entry point was executable.

`grasp init` disclosed Claude usage and possible cost before writing, showed the same array-wrapped hook shape that appeared on disk, installed 45-second `PreToolUse`, `PostToolUse`, and `Stop` hooks, preserved the repository root when invoked from a nested directory, and was idempotent on a second run.

The current official Claude Code hook reference still documents Grasp's JSON hard-gate shape, `systemMessage`, prompt identifier, project-local settings path, and exit-0 behavior. Stderr from an exit-0 hook goes only to Claude's debug log, which is important for Grasp's quiet internal error handling.

## 2. Diff capture and mechanical filtering — FAIL

### What worked

- Manual capture combined staged, unstaged, and untracked changes, with correct paths, statuses, line counts, and hunks.
- Hook capture used a session checkpoint. A repeated `PostToolUse` with no new work created no duplicate capture, model call, or cost.
- A later meaningful edit generated one capture and one model call containing only the newly added function, not the session's older uncommitted work.
- Lockfiles, Grasp's own hook settings, whitespace-only reindentation, a two-line change below the size floor, and a repository-specific ignored directory were filtered before generation.
- The same `ignored/` path in a second repository without the override reached generation, proving that the override was repository-specific.
- A tracked generated file whose unchanged header remained on disk was correctly filtered during a normal body regeneration. This fixes the exact main failure from the previous report.

### What is broken

Deleting a generated file bypasses generated-file detection.

The clean reproduction was:

1. Track a four-line file whose first line is `// Code generated by a tool. DO NOT EDIT.`.
2. Seed a fresh Grasp session checkpoint.
3. Delete the file.
4. Fire `PostToolUse`.

Grasp stored the capture with `filtered = 0`, invoked the mock Claude once, and created a real question event with this summary:

```text
1 file changed (+0/-4): generated.ts
```

The cause is direct in `src/filter.ts`: the disk check intentionally returns false for a deleted file, while the diff check looks only at added lines. The removed header is available in the deletion diff but is never examined. A generator removing an obsolete output file is routine, so this remains a real gap in the built-in generated-file claim.

## 3. Question generation and concept memoization — PASS (mocked)

- The custom mock recorded exactly one `claude -p` invocation with JSON output, an empty allowed-tools value, and one maximum turn.
- The prompt contained the significant hunk, not excluded files or the repository's full contents, and explicitly labeled diff text as untrusted data rather than instructions.
- A valid mock response produced a concept-first pair, stored the exact filtered diff, recorded the reported cost, and used the checkpoint tree range as the diff hash.
- After answering `input-validation` in repository A, the same mock response in repository B was forced to instance-only. The mock still returned a concept question, proving Grasp enforced cross-project memory itself.
- The installed real Claude executable accepted Grasp's invocation flags before returning its unauthenticated error envelope.
- Passing automated tests cover bad JSON, model-declared errors, missing costs, invalid tags, and a new concept missing its concept question.

Actual model question quality, tag consistency, and live authenticated hook behavior could not be judged in this unattended disposable environment.

## 4. Cost cap and question-count cap — FAIL

### What worked

- With a $0.01 cap and $0.006 mock calls on three turns sharing one `session_id`, the first two calls ran and recorded $0.012 total; the third logged `cap_reached` without invoking Claude. This matches the documented one-call crossing behavior.
- With a one-event question cap, the first turn generated one real event and the second logged `cap_reached` without invoking Claude.
- Mock call counters proved cap-blocked turns never invoked Claude.
- The automated six-process cap races passed.
- The prior slow-queue regression also passed independently: three same-session workers backed by 16-second mock calls finished at about 16, 20, and 32 seconds. Two calls succeeded, one logged `timeout`, every process stayed below the installed 45-second outer hook limit, and no generation reservation remained stuck.

### What is broken

`invokeClaudeJudge` accepts any JavaScript number from `total_cost_usd`; it does not require the value to be finite and non-negative.

In a direct mock response with `total_cost_usd: -0.5`, Grasp recorded a real question with `cost_usd = -0.5`, and `SUM(cost_usd)` for that session became `-0.5`. Future calls therefore see more room below the cap than the session really has. This is the same cost-integrity class as the already-fixed missing-cost bug: an invalid provider response must become a logged error miss, not alter the cap in the wrong direction.

## 5. `grasp review` answer, skip, and batch flow — FAIL

### What worked

- The real Ink interface was exercised in a pseudo-terminal and displayed repository, summary, colored hunk, question type, and batch counts readably.
- Doing nothing for several seconds did not advance or dismiss a question.
- Blank submissions were rejected for both concept and instance answers. SQLite stayed unchanged until real answers were supplied.
- Real concept and instance answers were saved, and only completion marked the linked concept learned.
- Escape deliberately opened the optional skip-reason step. Pressing Enter with a blank reason recorded a real skip and left the concept unlearned.
- A four-session pending batch was grouped by session with accurate overall and per-session counts.
- Running review without an interactive terminal failed clearly instead of hanging.

### What is broken

On the optional skip-reason screen, the footer says `[Esc] skip this question`, but Escape is disabled in that phase. A second Escape produced no state change and left the event pending; only Enter completed the skip. The placeholder does say Enter can leave the reason blank, so the workflow remains usable, but the displayed key instruction is false and should either work or be removed.

Terminal resizing during a live question was not reliably controllable through this unattended pseudo-terminal harness, so resize behavior remains unverified.

## 6. Soft and hard gate modes — PASS

- Soft mode emitted no denial while recent questions were pending.
- A hard-mode repository override loaded from a nested working directory and returned the current documented `PreToolUse` denial JSON for two pending questions in that session.
- A different session was not blocked.
- Answering both pending events immediately removed the denial.
- `Stop` combined the correct pending count with a four-decimal cumulative cost message.
- The automated age tests confirm that a question older than 24 hours remains visible to review and the Stop nudge but does not block a resumed session.

## 7. Error, timeout, config-failure, and interrupted-session handling — PASS

- A mock executable exiting nonzero produced an `error` miss, no pending question, exit code 0 from the internal hook, and no leaked child-process error.
- A mock that slept for 30 seconds was killed at about 20 seconds, logged a `timeout` miss, and returned normally without creating a phantom gate.
- A realistic invalid repository setting (`gateMod`) made `internal:hook` exit 0. Its diagnostic was written only to stderr, which current Claude Code documentation says is debug-log-only for exit-0 hooks. The same config still made an ordinary foreground command fail loudly with a clear validation message.
- Interrupted turns do not leave a waiting process: hooks are short-lived and state is durable. The documented narrow hard-kill window between capture and event recording remains, but normal errors and timeouts are logged.

The invalid negative-cost envelope is reported separately in section 4 because it specifically breaks cap accounting rather than process/timeout recovery.

## 8. Configuration loading and per-repository overrides — PASS

- The disposable global config was created with all documented defaults.
- Repository overrides changed hard-gate behavior, cost cap, question cap, ignore behavior, and nested threshold fields.
- Overrides resolved from a nested working directory to the Git root.
- The same custom ignore path was excluded in one repository and allowed in another.
- Arrays replace rather than concatenate, while nested objects merge by key, matching the documentation.
- Invalid JSON, invalid values, unknown top-level keys, and unknown threshold keys were rejected with actionable messages.

## 9. Fresh-eyes code and documentation review — FAIL

The source is generally readable and unusually well commented. The README is candid about on-demand review, Claude usage, local storage, cap overshoot, stale gates, checkpoint pruning, the hard-kill window, and the lack of full-week dogfooding. Current official Claude Code hook documentation matches the installed hook structure and hard-gate output.

Four inconsistencies remain:

1. The README says generated files are excluded before generation, but deleting a self-declared generated file reaches Claude and creates a paid question.
2. The README's install section calls Claude Code installation/authentication the requirement but never states the package's actual `node >=22` requirement. Both Grasp and `better-sqlite3@13.0.2` declare that engine floor, so someone on an older Node release is not given the prerequisite before trying the install.
3. The privacy/cost section says there are "no file reads beyond what's in the diff." The unchanged-header fix now reads up to 4 KB from each changed file on disk. That header data is used only for local filtering and is not sent to Claude, so this is wording accuracy rather than a new transmission concern, but the literal claim is false.
4. The review UI advertises Escape on the skip-reason screen even though that key does nothing there.

The original success criterion requiring a person to keep Grasp enabled during real work for a full week remains unverified, as the README correctly acknowledges.

## Additional bugs and risks found

1. Simultaneous processes racing to initialize a completely absent SQLite database can still hit `SQLITE_BUSY` while switching the new file into WAL mode. Normal setup creates the database before hooks are installed, so this remains mainly a risk if the user deletes the database while hooks are active.
2. Git diff parsing is line- and tab-delimited rather than NUL-delimited. Ordinary names, spaces, and renames are tested, but filenames containing tabs, newlines, or unusual leading/trailing whitespace remain a likely edge case.
3. Live authenticated Claude question quality, a genuine Claude Code hook firing, mid-question terminal resizing, and full-week human dogfooding could not be verified in this unattended run.

FINAL_VERDICT: FAIL
